## Key Instructions Sent to Agent

- Inspect and reuse the existing `models.py`, `registration_service.py`, `login_service.py`, `user_management_service.py`, `rbac.py`, and `bootstrap_admin.py`; keep controller roles and interactions aligned with the class and sequence diagrams.
- Implement `AuthController.register(name, email, password)`, `login(email, password)`, and `logout(token)`. Delegate registration/login to existing services and return safe user representations that never expose `password_hash` or `token_hash`.
- Implement `AdminUserController.view_users(token)` and `assign_role(token, user_id, role)`. Resolve the active token and enforce the `ADMINISTRATOR` role through `rbac.py`, then delegate to `user_management_service.py`.

Use 400 for validation, 401 for unauthenticated access, and 403 for non-admin access.
- Serve a functional demo at `/` with registration, login/logout, user listing, and administrator role assignment.
- Add controller and HTTP route tests, preserve dependency-free backend code, and update prompt/log and requirement traceability records with actual verification results.

## Integration Note

The existing services require an injected DB-API connection, and the repository does not configure or include a Python MySQL driver/connection factory. `app.py` exposes `create_app(auth_controller, admin_controller)` for deployment wiring/tests, plus `create_app_from_connection(connection)` and `serve(connection, host, port)` for a caller that supplies its approved MySQL adapter. No framework or alternate storage engine is introduced.
