# Task Prompt — `v0.1.0-design` (Increment 1 Architecture & UML Design)

## Objective

Design the initial architecture, UML diagrams, incremental development plan, and requirements traceability matrix for **Increment 1 (`v0.1.0-design`)** of the **Event & Volunteer Management System**, covering **UC01 (User Account & Authentication)** and **UC02 (User Management & RBAC)** (`FR-01`–`FR-04`, `FR-20`).

---

## Prompt 1: Use Case Diagram (`uml/use_case.puml`)

> Simplify the Increment 1 Use Case Diagram so it strictly covers `UC01: User Account & Authentication` and `UC02: User Management & RBAC`.
> - Remove deferred Increment 2–4 use cases (`UC03`–`UC07`) and external adapters (`Email Service`, `Cloud Backup Storage`).
> - Model `Event Organizer`, `Volunteer`, and `Administrator` inheriting from the parent `User` actor via generalization arrows.
> - Associate `User` with `UC01` and `Administrator` with `UC02`.

## Prompt 2: Simplified Class Diagram (`uml/class_diagram.puml`)

> Simplify the Increment 1 Class Diagram from a 12-class layered architecture down to the 4 core classes/enums required for `v0.1.0`:
> - `User` (`id: UUID`, `name: String`, `email: String`, `passwordHash: String`, `role: UserRole`; `verifyPassword(password: String): Boolean`, `hasRole(role: UserRole): Boolean`)
> - `UserRole` enum (`ADMINISTRATOR`, `EVENT_ORGANIZER`, `VOLUNTEER`)
> - `AuthController` (`register(name, email, password): User`, `login(email, password): Boolean`, `logout(): void`)
> - `AdminUserController` (`viewUsers(): List<User>`, `assignRole(userId: UUID, role: UserRole): User`)
> - Add UML multiplicities (`1` to `0..*` from controllers to `User`, and `0..*` to `1` from `User` to `UserRole`).

## Prompt 3: High-Level & Low-Level Sequence Diagrams (`uml/sequence-diagrams/`)

> Create 4 separate PlantUML sequence diagrams matching `UC01`, `UC02`, and the simplified Class Diagram:
> - `SD01_High_Level_UC01_Auth.puml`: Black-box system sequence for `register()`, `login()`, and `logout()`.
> - `SD02_High_Level_UC02_UserManagement.puml`: Black-box system sequence for `viewUsers()` and `assignRole()`.
> - `SD03_Low_Level_UC01_Auth.puml`: White-box interactions between `User`, `:AuthController`, and `:User` (including `<<create>>` with default `UserRole.VOLUNTEER` and `verifyPassword()`).
> - `SD04_Low_Level_UC02_UserManagement.puml`: White-box interactions between `Administrator`, `:AdminUserController`, and `:User`.

## Prompt 4: Combined Swimlane Activity Diagram (`uml/activity-diagrams/AD_Increment1_Combined.puml`)

> Create a single swimlane PlantUML activity diagram combining `UC01` (`|User|` and `|System (AuthController)|`) and `UC02` (`|Administrator|` and `|System (AdminUserController)|`) from a single `start` node without `fork`/`partition` swimlane conflicts.

## Prompt 5: Persistence ERD (`uml/erd_increment1.puml`)

> Create the Increment 1 ERD scoped strictly to user accounts and roles (`User` entity with `id`, `name`, `email`, `password_hash`, `role`, `created_at`, `updated_at`), deferring `Event`, `Application`, `Task`, and `Attendance` to later increments.

## Prompt 6: Documentation & Traceability (`/docs/`)

> - Create `/docs/incremental_development_plan.md` with the 5-column roadmap (`v0.1.0-design` through `v1.0.0`) and per-version Main Question, Tools, and Acceptance Criteria.
> - Create `/docs/traceability_matrix.md` mapping `FR-01`–`FR-21` and `NFR-01`–`NFR-25` to Increment 1–4 artifacts and test paths, including the design-to-code synchronization policy.
