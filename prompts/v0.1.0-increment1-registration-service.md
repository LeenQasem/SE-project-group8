# Task: Implement the Registration Service – Increment 1

## Objective
Implement the Registration Service for the Event & Volunteer Management System as part of Increment 1 (Authentication and User Management).

The service must work with the existing User and Role models, the current MySQL database implementation, and the approved project architecture.

**Approved Technology Stack:**
- Frontend: React
- Backend: Python
- Database: MySQL

Do not introduce a different technology or framework.

- The seed data, particularly the default Volunteer role.
- The Increment 1 requirements and architecture documentation.

Use the existing implementation as the source of truth. Do not recreate or duplicate functionality that already exists.

## 2. Implement the Registration Service

Create the Registration Service in the appropriate location within the existing backend structure.

The service must handle the complete user registration process.

### Required functionality

1. **Input validation**
   - Accept the required registration information according to the existing User model and requirements.
   - Validate that required fields are provided.
   - Validate email format.
   - Validate password requirements according to the existing project requirements.
   - Reject invalid registration data with appropriate errors.

2. **Email uniqueness**
   - Check whether the email address is already registered.
   - Prevent duplicate user registrations.
   - Handle database uniqueness violations safely, including concurrent registration attempts.

3. **Password security**
   - Hash the user's password securely before storing it.
   - Never store plain-text passwords.
   - Never return password hashes in registration responses.
   - Use an established password-hashing library if one is already configured. If not, select an appropriate secure Python solution without unnecessarily changing the project dependencies.

4. **Default role assignment**
   - Automatically assign the `Volunteer` role to newly registered users.
   - Do not allow users to select or assign themselves an Administrator or Event Organizer role through public registration.
   - Retrieve the default role from the existing roles table rather than hardcoding a role ID.
   - Handle the situation where the Volunteer role does not exist.

5. **Database persistence**
   - Save the newly registered user in the existing MySQL database.
   - Use the existing database connection and SQL operations wherever possible.
   - Ensure the registration operation is handled safely and consistently.
   - Do not create duplicate database tables or modify the existing schema unnecessarily.

6. **Response handling**
   - Return an appropriate success response when registration is completed.
   - Return meaningful errors for invalid input, duplicate emails, missing default roles, and database failures.
   - Return only appropriate user information, never sensitive authentication data.
